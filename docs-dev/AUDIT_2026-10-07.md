## Продукт и информационная архитектура

Ежедневный цикл: открыть Next Action → перейти к нужной фазе → выполнить самостоятельную работу → отметить освоение/практику → сохранить evidence → подтвердить checkpoint → получить следующее действие. Dashboard и рабочие controls должны поддерживать этот цикл раньше справочников и recovery.

Текущий порядок значимости:

1. Next Action, рабочая фаза, её controls, evidence/checkpoint.
2. Сегодня, blocker/ближайшая задача, roadmap и основной проект.
3. Регулярная No-AI практика, ошибки, interview, career/vacancy.
4. Нагрузка/оценки, рынок/версии, ресурсы и справочники.
5. Import/export, snapshots, backup, история — доступны через «Ещё»/историю, без постоянного акцента.

Алгоритм Next Action не переписан: он учитывает prerequisite checkpoints, активную доступную фазу, setup, незакрытую practice, слабые темы/действия и задания checkpoint. Добавленные domain tests проверяют переход setup→practice→checkpoint→следующая фаза, приоритет активной доступной ветки и повторную блокировку зависимостей. Текстовые blocker/next15 остаются пользовательскими заметками; автоматического понимания свободного текста нет.

Основной горизонтальный board остаётся плотным и содержит много controls. Вместо создания четвёртого интерфейса сохранены три уже подготовленных способа disclosure: Atlas — связи и выбранный этап, Session — один этап с подготовкой/практикой/результатом, Ledger — раскрываемые строки. Выбор между ними требует решения пользователя.

Визуально сохранены нейтральные поверхности, семантические статусы и темы. Не добавлены декоративные градиенты, карточки, badges, animations, icons или зависимости. Уменьшен заголовок Dashboard 40→24 px на desktop и 34→22 px на narrow layout. Основные phase mastery-select и evidence в главном сайте используют 13 px вместо прежних 11 px.

## Архитектура, delivery и security review

Проверены package/lock, scripts, workflow, main/index/styles/appearance, app, data/domain/state/cloud, migrations, tests, README и CLOUD_SETUP. Сохранены vanilla JS, pure domain, defensive state validation, HTTP transport и отдельная cloud orchestration. Размер app.js сам по себе не стал основанием для разбиения.

Существующие performance-решения сохранены: reuse неизменившихся phase cards, зависимые render signatures, rAF для поиска/drag и `content-visibility` для вторичных sections. ARIA-атрибуты disclosure задаются при создании изменившейся карточки, без повторной разметки всех фаз при каждом обновлении.

Build по-прежнему minifies и создаёт hashed JS/CSS; manifest удерживает текущую и одну предыдущую локальную генерацию. Это не проверка всех возможных stale-cache сценариев после нескольких деплоев. CSP не ослаблялся. Workflow использует read-only contents permission и pinned checkout/setup-node; browser dependencies остаются dev-only.

Security-классификация:

- Публичный publishable key — допустимая браузерная конфигурация, не утечка секрета. Привилегированные ключи в просмотренном browser source не обнаружены.
- В SQL RLS включён; SELECT ограничен auth.uid(); прямые записи normal authenticated client отозваны; запись через security-definer RPC с пустым search_path, auth-derived user ID, проверкой revision/payload/schema и transaction lock.
- В клиенте сохранены тристороннее объединение, локальные поля, явный first-sync/conflict choice, CAS retry и сохранение правок во время upload.
- User text выводится через escaping/textContent; vacancy URL проходит safeURL. Browser fixtures с HTML и javascript: URL не исполнились в проверенных путях.
- Реальные RLS/grants/auth email/database не тестировались. Историческое утверждение CLOUD_SETUP о проверке 06.10.2026 не считается проверкой этого аудита.

## Performance: измерения before/after

Метод: один и тот же `test-results/audit-inspect.cjs`, изолированный headless Edge, desktop 1440×900, reduced motion, без CPU/network throttling. 30 mastery changes, 100 поисковых input с ожиданием rAF, 30 evidence input. Время mastery/evidence — синхронный обработчик; search включает ожидание кадра. Это не INP, Lighthouse score или замер реального телефона.

| Измерение | До | После |
| --- | ---: | ---: |
| Production JS, raw bytes | 89 479 | 90 779 |
| Production CSS, raw bytes | 28 488 | 28 945 |
| HTML, bytes | 42 427 | 42 468 |
| DOM elements в сценарии | 3 042 | 3 042 |
| Mastery handler median / p95, ms | 11,9 / 24,9 | 9,9 / 17,2 |
| Search frame median / p95, ms | 28,5 / 38,3 | 11,2 / 33,7 |
| Evidence handler median / p95, ms | 0,2 / 0,4 | 0,2 / 0,4 |
| Progress writes: debounce + pagehide | 2 | 1 |

Эти timings — отдельные серии, а не статистическое доказательство ускорения. В промежуточных сериях search median был около 27–28 ms, поэтому разницу нельзя приписывать исправлению алгоритма поиска: он не менялся. Устойчивое ускорение интерфейса не заявляется. Подтверждённое уменьшение работы — устранённая повторная storage-запись. Значимого постоянного performance bottleneck в выполненных сценариях не найдено. JS вырос на 1 300 байт из-за защиты данных и взаимодействий; runtime dependencies не добавлены.

Исходные данные: `test-results/audit/before/measurements.json` и `test-results/audit/after/measurements.json`.

В окружении доступен Node 24.19.0 и скопированные dependencies, но нет команды npm. `npm ci --ignore-scripts` не выполнялся. Команды package scripts запущены напрямую:


Результаты: 11/11 unit tests; main и три preview builds успешны; все три browser suites прошли. Повторный main build оставил `docs/` побайтно неизменным (проверено SHA-256 всех файлов). Browser запускался вне sandbox, где Edge доступен; все данные тестов изолированы от пользовательского профиля.

UI suite проверяет основной учебный цикл до pass, dependencies/Next Action, controls/focus, меню/drawer/modal, debounce/immediate writes, import/export и rejected imports, HTML escaping, No-AI/mistakes/career/vacancy, snapshot restore/backup, reload, schema 2, corrupt/blocked/quota storage и защиту устаревшей вкладки с recovery. Cloud suite проверяет mocked first/second device, offline merge, конфликт, CAS retry, edits-during-upload, reload и refresh. Deletions/arrays покрываются unit merge tests; list conflict end to end отдельно не проверялся.

Main: 360×800, 390×844, 430×932, 768×1024, 1440×900, 1920×1080, обе темы. На этих layouts не обнаружено page-level overflow. Проверены рабочие sections, forms и границы dialogs. Скриншоты просмотрены, включая checkpoint, login и cloud conflict. Все три варианта проверены runner на 360/390/768/1440 и визуально просмотрены на desktop/phone/tablet. Материалы:

## Оставшиеся ограничения

- Read-before-write защита обнаруживает уже завершённое чужое сохранение. localStorage не предоставляет атомарный CAS: строго одновременная гонка между проверкой и записью не доказана защищённой. Автоматическое объединение локальных вкладок не добавлялось; при обнаруженном конфликте нужен экспорт/reload/осознанный import.
- Не тестировались реальные email/auth/RLS/RPC Supabase, physical touch scrolling, экранная клавиатура iOS/Android, Safari/Firefox и реальный screen reader.
- Не измерялись cold mobile load, CPU-throttled INP и долговременный профиль с близким к лимиту объёмом истории.
- Новая конфигурация GitHub Actions проверена локальными эквивалентами команд; сам remote CI не запускался.
- Рыночные/версионные утверждения curriculum не перепроверялись как отдельное внешнее исследование и не менялись.
- Превью намеренно не подключают cloud и сохраняют отдельный префикс. Ни один вариант не выбран для публикации; сайт не публиковался.

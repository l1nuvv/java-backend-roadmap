# Контекст для продолжения в Codex

Состояние на 7 октября 2026 года.

## Запрос пользователя

Пользователь хотел три действительно разных интерфейса Java Backend Roadmap. После просмотра локальных вариантов оставил для выбора Atlas и Session; Ledger не нравится из-за табличной композиции. Пользователь выбрал компактный Session и 7 октября 2026 явно запросил публикацию на GitHub Pages. Сейчас проект выделен в самостоятельную локальную папку для дальнейшей работы в Codex.

## Готовые варианты

1. **Atlas / карта зависимостей:** граф реальных prerequisite-связей 13 этапов; выбранный этап справа. На телефоне доступен выбор этапа и раскрытие карты.
2. **Session / рабочая сессия:** один активный этап; отдельные части «Подготовка», «Практика», «Результат»; контекст и текущее действие слева. На телефоне состояние этапа раскрывается отдельно.
3. **Ledger / реестр:** все этапы в таблице; строки раскрывают реальные поля темы, практики, evidence и checkpoint.

Исходники: `designs/src/`. Варианты используют `src/app.js`, общие данные и доменную модель, а не выдуманные показатели. Все разделы приложения доступны через навигацию. У каждого варианта есть светлая и тёмная темы.

## Что сохранено

- Текущие локальные исходники основного сайта в `src/`, включая незавершённый ранее внешний вид. Это текущая рабочая копия, а не утверждение о совпадении с опубликованной версией.
- Все документы из нового пользовательского архива: `AGENTS.md`, `docs-dev/`, repo-scoped `frontend-design` skill и оба reference-файла.
- Основной сайт и новая сборка сравнения дизайнов.
- Тесты доменной модели и облака; отдельный переносимый браузерный тест трёх вариантов.
- SQL-миграции Supabase и публичная конфигурация существующего проекта.

Дизайны не монтируют cloud controller; CSP запрещает сетевые подключения в превью. Предпросмотр хранит отметки под отдельным префиксом `distinct-preview:` и не затрагивает ключи рабочего сайта. Основной сайт сохраняет исходные ключи и облачную логику.

## Важные ограничения

- Сохранять `schemaVersion = 3`, ключи `javaRoadmapV3*`, IDs `p0`…`p12`, порядок индексируемых тем и практики.
- Не менять семантику setup/concept/action, prerequisite и checkpoint ради внешнего вида.
- Не ослаблять RLS, RPC, optimistic revision и трёхстороннее объединение.
- Публичный Supabase publishable key допустим в браузере; секреты и сессии в исходники не добавлять.
- Источник дизайнов — `designs/src/`, не `previews/distinct/app.js`.
- Использовать узкие проверки по задаче. Не создавать ZIP/релизные пакеты без прямой просьбы пользователя.

## Проверено перед выделением папки

Доменная логика: 6 тестов. Для каждого нового интерфейса: 13 этапов, отметки настройки/темы/практики, evidence, открытие checkpoint, dashboard, no-AI сессия, дополнительные разделы, сохранение после reload, поиск, фильтры, focus, темы, навигация и границы диалога на 360/390/768/1440 px. Скриншоты соответствующих размеров визуально просмотрены. В превью не было внешних запросов или ошибок JavaScript.

Браузерные проверки облака используют имитацию API; изменения дизайнов не требуют миграции Supabase. Новые интерфейсы пока не опубликованы на GitHub Pages.

После переноса в самостоятельную папку повторно успешно выполнены `node scripts/build-all.mjs`, 6 доменных тестов, браузерные проверки всех трёх интерфейсов и `tests/cloud.browser.cjs`. Все проверки использовали зависимости внутри новой папки; тест дизайнов запускал собственный сервер на случайном порту. Старый сервер на 8768 для этих проверок не требовался.

## Публикация выбранного Session

Компактный Session перенесён в основной сайт. Общая реализация находится в `src/ui/learning-interface.js` и `src/ui/learning.css`; `designs/src/` использует её для превью. Основной сайт не импортирует preview storage shim, сохраняет исходные ключи schema 3 и монтирует Supabase controller. Предупреждения восстановления вынесены из раздела «Сегодня» в общую область. Переход к текущему этапу показывает правильный экран до фокусировки. Сборка сохраняет assets предыдущей опубликованной версии для кешированного HTML.

Публикация: GitHub-репозиторий `l1nuvv/java-backend-roadmap`, Pages из `main/docs`; рабочая копия с историей для отправки находится в `test-results/publish-repo/`. Проверки перед отправкой: unit, build-all, production UI, mocked cloud (включая fragment callback), все три preview layouts, desktop/mobile screenshots. Реальный вход и live RLS/RPC не проверяются этими тестами.

Session опубликован коммитом `9eb0d24`; публичные HTML/assets совпали со сборкой, проверены 360/390/768/1440 в обеих темах, навигация и облачный диалог без реального входа. CI Linux выявил переполнение при 360 px. Поиск вынесен отдельной строкой, действия переносятся внутри панели. Диагностика подтвердила, что горизонтальная навигация шапки прокручивается внутри компонента; добавлена проверка доступности последней ссылки при фокусировке. Длинные подписи метрик переносятся внутри узких колонок; добавлен регрессионный сценарий с широкими fallback-символами. Повторный Linux CI ожидается. Команда установки браузера в CI уточнена как `npm exec -- playwright install --with-deps chromium`.

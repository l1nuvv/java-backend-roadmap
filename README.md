# Java Backend Roadmap 3.4

Сайт: https://l1nuvv.github.io/java-backend-roadmap/

Трекер обучения с 13 фазами, checkpoint, dashboard и синхронизацией между устройствами. Данные предыдущей версии сохранены: schemaVersion 3 и ключи localStorage не меняются.

## Разработка

Node.js 24, npm. Выполните npm ci --ignore-scripts, npm test, npm run build. Сборка публикует только папку docs. Для локального просмотра запустите HTTP-сервер из docs; открытие через file:// не поддерживается ES-модулями.

Браузерные проверки: npm exec playwright install chromium, затем npm run test:browser. Для уже установленного браузера можно задать ROADMAP_BROWSER_PATH. Тесты используют изолированные профили и имитацию API, не отправляют настоящие письма и не меняют данные Supabase.

## Структура

- src/data — учебные данные и типы отметок.
- src/domain — вычисление readiness, checkpoint, прогресса и Next Action.
- src/state — валидация и совместимая миграция состояния.
- src/app.js — интерфейс и локальное сохранение, без глобального доступа к состоянию.
- src/cloud — трёхстороннее объединение, транспорт и управление сессией/синхронизацией.
- src/config.js — публичный адрес проекта и Publishable key.
- supabase/migrations — исходная схема и применённое усиление проверки данных.
- tests — проверки миграции, доменной логики, конфликтов и опасных импортов.
- docs — готовая статическая сборка GitHub Pages.

## Синхронизация

Войдите по одному email на всех устройствах через «Облако». При первом входе на следующем устройстве выберите «Взять из облака». Разные поля объединяются автоматически; одновременные несовпадающие изменения одного поля требуют выбора. Списки считаются единым полем. Тема, масштаб, фокус и локальные snapshots не синхронизируются.

Проект настроен для личного использования: новые регистрации закрыты в Supabase. Existing users могут входить по email; отправка письма не создаёт аккаунт. Для разрешения нового пользователя требуется действие владельца в Supabase Dashboard.

## Безопасность

Publishable key по назначению открыт и виден в исходниках браузера. Он не является административным ключом. Чтение прогресса ограничено RLS по auth.uid(); прямые записи запрещены. RPC берёт user_id из сессии, проверяет schema/размер данных и ожидаемую ревизию, затем обновляет в транзакции. Анонимный доступ к таблице и RPC запрещён.

Пароли, service_role/secret key и токены сессий не входят в репозиторий. Настройки базы отсутствуют в пользовательском интерфейсе. CSP ограничивает исполняемые скрипты своим сайтом, сетевые запросы — этим сайтом и указанным Supabase. Авторизационные ссылки очищаются от токенов после обработки. Токены остаются в локальном браузерном хранилище, как и раньше; защиту браузера нельзя заменить скрытием публичного ключа.

GitHub Actions проверяет тесты и воспроизводимость сборки с read-only правами, закреплёнными SHA официальных Actions и без сохранения GitHub credentials.

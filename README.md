# Java Backend Roadmap — локальный проект для Codex

Основной сайт использует выбранный компактный Session с облачной синхронизацией. В проекте также сохранены три локальных варианта интерфейса. Её можно целиком открыть как проект в Codex. Исходники, инструкции, зависимости, сборки и тесты находятся внутри; предыдущая рабочая папка для запуска не нужна.

## Открытие в Codex

Добавь эту папку через выбор папки проекта:

```text
C:\Users\l1nuvv\Documents\Codex\java-backend-roadmap-project
```

Инструкции для агента: `AGENTS.md`. Контекст текущей работы: `CURRENT_WORK.md`. Дизайн-скилл: `.codex/skills/frontend-design/SKILL.md`.

## Быстрый запуск

Нужен Node.js 24. Локальные зависимости уже скопированы в `node_modules`, поэтому в текущем окружении можно запускать команды напрямую через `node`. После переноса на другой компьютер для чистой установки зависимостей используй Node.js с npm и `npm ci --ignore-scripts`.

Из этой папки:

```powershell
node scripts/serve.mjs
```

Открой http://127.0.0.1:8770/ — сравнение Atlas и Session (Ledger сохранён как предыдущий вариант):

- `distinct/atlas.html` — карта зависимостей;
- `distinct/session.html` — рабочая сессия;
- `distinct/ledger.html` — реестр программы.

Варианты работают локально, используют отдельное пространство сохранения `distinct-preview:*` и не подключаются к Supabase. Между тремя вариантами в одном браузере превью прогресс общий.

Для основного сайта из текущих локальных исходников:

```powershell
node scripts/serve.mjs --site
```

Открой http://127.0.0.1:8771/. У основного сайта сохранена публичная конфигурация Supabase. Локальное хранилище каждого адреса сайта отдельное. Для входа с localhost адрес должен быть разрешён владельцем в настройках Supabase; настройки облака описаны в `CLOUD_SETUP.md`.

Команда запуска сервера ничего не публикует. Остановка — `Ctrl+C`. Если порт занят, перед запуском задай другой через `$env:PORT = '8772'`.

## После изменений

```powershell
node scripts/build-all.mjs
```

Команда обновит основной сайт в `docs/` и дизайн-превью в `previews/`. Отдельные команды: `node scripts/build.mjs` и `node scripts/build-designs.mjs`. При наличии npm доступны также `npm start`, `npm run start:site`, `npm run build:all` и другие команды из `package.json`. Сборка не зависит от текущей рабочей директории скрипта и не обращается к старой папке проекта.

## Проверки

```powershell
node --test tests/merge.test.mjs
node tests/designs.browser.cjs
```

Для браузерных тестов используй установленный Chromium через `npm exec playwright install chromium` или укажи путь к браузеру. Пример для Windows:

```powershell
$env:ROADMAP_BROWSER_PATH = 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
node tests/designs.browser.cjs
```

Браузерный тест дизайнов проверяет три интерфейса, отметки, evidence, checkpoint, поиск, фильтры, сохранение, темы, навигацию и диалоги при ширинах 360/390/768/1440. Тест сам запускает временный локальный сервер и сохраняет скриншоты в `test-results/designs/`. Перед прямым запуском теста после правок пересобери дизайны. Команда `npm run test:designs` делает это автоматически.

`node tests/cloud.browser.cjs` проверяет собранный основной сайт и синхронизацию с имитацией API. Команда `npm run test:browser` сначала пересобирает сайт, затем запускает эту же проверку. Эти тесты не отправляют письма и не меняют реальную базу Supabase.

`node tests/ui.browser.cjs` проверяет основной учебный сценарий, клавиатуру, меню и диалоги, импорт/экспорт, миграцию v2, сбои localStorage и шесть размеров экрана в двух темах. Перед прямым запуском пересобери сайт; при наличии npm можно использовать `npm run test:ui`. Скриншоты сохраняются в `test-results/ui/`.

Технический и UX-аудит локальной версии: `docs-dev/AUDIT_2026-10-07.md`.

## Структура

```text
AGENTS.md                    Правила работы с проектом
CURRENT_WORK.md               Что готово и что делать дальше
README.md                    Запуск и команды
CLOUD_SETUP.md               Настройки облака
docs-dev/                    Все контракты из переданного архива
.codex/skills/frontend-design/ Дизайн-скилл и справочники
src/                         Основное приложение и общая логика
designs/src/                 Точка входа локальных превью
designs/comparison.html      Исходник страницы сравнения
designs/screenshots/         Сохранённые изображения вариантов
scripts/                    Сборка и локальный сервер
tests/                      Доменная логика, облако, три дизайна
supabase/migrations/         Схема и усиление защиты базы
docs/                       Сборка основного сайта
previews/                   Сборка трёх интерфейсов
package.json                Команды и зависимости
package-lock.json           Зафиксированные версии зависимостей
```

Править нужно исходники, затем пересобирать. `docs/` и `previews/` — генерируемые результаты. `designs/screenshots/` — визуальные ориентиры предыдущей проверки; для актуальных снимков после изменений запусти браузерный тест дизайнов.

Прогресс хранится в браузере и Supabase, а не в файлах проекта. Для переноса локального прогресса используй экспорт/импорт в приложении. Личные сессии и пользовательские записи в эту папку не копировались.

Существующий опубликованный сайт: https://l1nuvv.github.io/java-backend-roadmap/. Репозиторий: https://github.com/l1nuvv/java-backend-roadmap. GitHub Pages публикует `docs/` из ветки `main`. Локальная рабочая папка хранит актуальные исходники; подготовленная копия с Git-историей для публикации находится в `test-results/publish-repo/` и не включается в репозиторий.

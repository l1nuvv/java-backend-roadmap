# Синхронизация прогресса

Сайт остаётся на GitHub Pages. Supabase хранит прогресс под аккаунтом пользователя.

## Однократная настройка владельцем

1. В Supabase → SQL Editor выполните весь `supabase-setup.sql`.
2. В Authentication → URL Configuration установите Site URL `https://l1nuvv.github.io/java-backend-roadmap/` и добавьте этот же адрес в Redirect URLs.
3. В Authentication → Providers включите Email. В стандартной конфигурации письмо содержит ссылку входа. Для входа по коду можно добавить `{{ .Token }}` в шаблон Magic Link в Authentication → Email Templates.
4. `cloud-config.js` содержит только Project URL и публичный Publishable key. Secret/service_role key в сайт и репозиторий не добавляются.

## На компьютере и телефоне

Нажмите «Облако», укажите одинаковый email и запросите письмо. Откройте ссылку на том устройстве, где входите, или введите код, если письмо содержит его. На первом устройстве локальные отметки отправятся в пустое облако. На следующем устройстве выберите «Взять из облака» при первом входе. Первоначальный выбор нужен, чтобы случайно не заменить уже сохранённые отметки.

Изменения отправляются автоматически после локального сохранения. Открытая вкладка проверяет облако каждые 15 секунд, при возвращении в приложение и восстановлении соединения. Кнопка «Синхронизировать сейчас» обновляет сразу. При отсутствии интернета изменения сохраняются локально и отправляются после подключения и восстановления сессии.

Разные изменённые поля объединяются автоматически. Если обе стороны изменили одно поле по-разному, выберите версию для спорных пунктов в окне «Облако». Списки записей считаются единым полем: одновременные изменения одного списка требуют выбора версии. Несовпадающие остальные поля сохраняются. Неотправленные изменения, сделанные во время запроса, остаются локальными и отправляются следующим запросом.

Тема, фокус, масштаб, свёрнутые фазы и локальные snapshots не синхронизируются. Автоматический backup сохраняется перед заменой локального прогресса. Экспорт/Импорт остаются доступны.

## Доступ к данным

Таблица разрешает чтение только собственного `user_id` через RLS. Запись проходит через RPC, который берёт пользователя из текущей сессии, проверяет ожидаемую ревизию и выполняет обновление в транзакции. Прямые записи и анонимный доступ к таблице запрещены. Аккаунты разных пользователей не объединяются автоматически: при первом подключении каждого аккаунта нужен начальный выбор.

Настоящие письма, настройки почтового провайдера и права доступа проверяются после запуска SQL в вашем проекте. Браузерные тесты с имитацией API проверяют синхронизацию и конфликты, но не заменяют эту проверку.
